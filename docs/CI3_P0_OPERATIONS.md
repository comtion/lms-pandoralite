# CI3 P0 operations

Required production environment:

```text
LMS_ENCRYPTION_KEY=<at-least-32-random-characters>
LMS_COOKIE_SECURE=true
LMS_CSRF_ENABLED=true
LMS_MAIL_FROM=noreply@example.com
```

The Docker Compose defaults are for local development only. In production,
override the development encryption key, enable secure cookies only after
HTTPS is active, and configure a real mail transport.

Run `database/migrations/20260724_ci3_p0_foundation.sql` before enabling the
new endpoints.

Suggested cron jobs (run from the project root):

```text
*/5 * * * * php index.php ops dispatch_notifications 100
10 1 * * * php index.php ops generate_reminders 7
15 2 * * * php index.php ops backup database
30 2 * * 0 php index.php ops backup uploads
45 3 * * * php index.php ops cleanup 90
```

The local Docker stack runs these commands through the
`php84-lms-scheduler` service. It records one stamp per scheduled period below
`storage/scheduler` so restarts do not duplicate daily or weekly jobs.

Monitoring endpoints:

- `/health/ready` exposes only readiness state and is safe for a load balancer.
- `/health/details` requires an authenticated administrative session.

Backups are written below `storage/backups`, checksummed, and recorded in
`lms_backup_runs`. A restore must always be rehearsed in a non-production
environment before it is used in production.

## Restore rehearsal

Backups generated by the current `Ops` controller include session-scoped
compatibility guards for legacy zero dates and foreign-key creation order.
They do not change the global MySQL mode.

```text
CREATE DATABASE lms_restore_rehearsal CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
gzip -dc storage/backups/database-YYYYMMDD-HHMMSS.sql.gz |
  mysql -h DB_HOST -u DB_USER -p lms_restore_rehearsal
```

After importing, compare the table count and critical row counts with the
source database. Drop only the explicitly named rehearsal database after the
checks pass.
